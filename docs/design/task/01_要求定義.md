# 要求定義書 — タスク管理アプリ

| 項目 | 内容 |
|---|---|
| 文書の位置づけ | 発注者(業務側)の「困りごと・実現したいこと」を整理する。実現手段はまだ書かない |
| 対象 | タスク管理アプリ(研修テンプレート) |

## 1. 背景

開発チーム内のタスクが個人のメモ・チャット・口頭に散在しており、以下の問題が起きている。

- 誰が何をやっているか・何が残っているかが見えない
- 依頼したタスクが忘れられ、後工程に遅延が波及する
- 状況確認のための口頭・チャットでの問い合わせが頻発している

## 2. 目的

チームのタスクを一箇所に集約し、**「残っている作業が誰でもすぐ分かる」状態**を作る。

## 3. ステークホルダー

| 立場 | 関与 |
|---|---|
| チームメンバー | タスクの登録・更新・完了を日常的に行う |
| チームリーダー | 残タスクの把握に利用する |

## 4. 実現したいこと(要求)

| # | 要求 |
|---|---|
| R-1 | タスクを簡単に登録できること(登録が面倒だと使われなくなる) |
| R-2 | 残っているタスクと完了したタスクが一目で区別できること |
| R-3 | 不要になったタスクを消せること |
| R-4 | チームの誰でも、どこからでもブラウザで使えること |

## 5. スコープ外(今回はやらないこと)

- ユーザー認証・担当者の割り当て(まずは全員共用で開始する)
- 通知・リマインド機能
- モバイルアプリ

## 6. 制約

- 研修標準の技術スタック(React / Spring Boot / PostgreSQL / Lightsail)を使用すること
