# 要件定義書 — タスク管理アプリ

| 項目 | 内容 |
|---|---|
| 文書の位置づけ | 要求定義を「システムとして何を作るか」に落とし込む。要求との対応を明示する |
| 上位文書 | [01_要求定義.md](./01_要求定義.md) |

## 1. 機能要件

| # | 機能 | 内容 | 対応要求 |
|---|---|---|---|
| F-1 | タスク一覧表示 | 全タスクを登録順に一覧表示する。完了/未完了が視覚的に区別できる。残件数を表示する | R-2 |
| F-2 | タスク登録 | タイトル(必須・100文字以内)と説明(任意・500文字以内)で登録できる | R-1 |
| F-3 | 完了状態の切り替え | 一覧上の操作で完了⇔未完了を切り替えられる | R-2 |
| F-4 | タスク削除 | 一覧上の操作でタスクを削除できる | R-3 |

### 入力チェック

| 対象 | ルール | エラー時の挙動 |
|---|---|---|
| タイトル | 必須、100文字以内 | 登録せずエラーメッセージを表示する |
| 説明 | 500文字以内 | 同上 |

## 2. 非機能要件

| 分類 | 要件 | 対応要求 |
|---|---|---|
| アクセス | HTTPSでインターネット経由で利用できる | R-4 |
| 対応環境 | PCのモダンブラウザ(Chrome / Edge 最新) | R-4 |
| 性能 | 通常操作のレスポンスは体感で遅延を感じないこと(目安1秒以内)。同時利用は10名程度を想定 | — |
| 可用性 | 業務時間帯に利用できること。計画停止は事前周知でよい(SLAは定めない) | — |
| データ | タスクデータはサーバー再起動後も保持されること | — |

## 3. 制約事項

- 技術スタック・アーキテクチャは研修標準(CLAUDE.md)に従う
- 認証は実装しない(スコープ外)

## 4. 受入基準(抜粋)

- タスクを登録すると一覧の末尾に表示される
- タイトル空で登録するとエラーメッセージが表示され、登録されない
- 完了に切り替えたタスクは取り消し線等で視覚的に区別され、残件数が減る
- 削除したタスクは一覧から消え、再読み込み後も復活しない
