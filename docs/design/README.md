# 設計書ディレクトリ

設計書は**システム(ドメイン)単位のサブディレクトリ**で管理します。
どのシステムも同じ4文書構成(要求定義 → 要件定義 → 基本設計 → 詳細設計)で作成します。

```
docs/design/
├── task/        # タスク管理(テンプレート同梱のお手本。まずこれを読む)
├── stock/       # 在庫管理(Phase 5 で受講者が基本設計から作成する)
└── {system}/    # 以降のシステムも同様にディレクトリを追加していく
```

## ルール

- 新しいシステムの設計書は `docs/design/{システム名}/` を作成し、[task/](./task/) と同じ構成・粒度で書く(文書の役割は [task/README.md](./task/README.md) 参照)
- 要求定義・要件定義が講師から支給される課題では、01・02は書かず `docs/assignment/{システム名}/` を参照し、03_基本設計から作成する
- 機能の追加・変更時は、コードと同じPRで該当システムの基本設計・詳細設計を更新する(CLAUDE.md「設計ドキュメントのルール」)
