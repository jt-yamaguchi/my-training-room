## 1. テーブル定義書

### tasks(タスク)

| カラム | 型 | NULL | 既定値 | 説明 |
|---|---|---|---|---|
| id | BIGINT (IDENTITY) | 不可 | 自動採番 | 主キー |
| title | VARCHAR(100) | 不可 | — | タイトル |
| description | VARCHAR(500) | 可 | — | 説明 |
| done | BOOLEAN | 不可 | FALSE | 完了フラグ |
| created_at | TIMESTAMP WITH TIME ZONE | 不可 | CURRENT_TIMESTAMP | 登録日時 |

- 対応マイグレーション: `V1__create_tasks.sql`(定義)、`V2__insert_seed_tasks.sql`(初期データ)
- インデックス: 主キーのみ(検索要件が増えたら追加を検討)

## 2. バリデーション仕様

| 対象 | ルール | 実装箇所 |
|---|---|---|
| title | 必須(空白のみ不可)、100文字以内 | TaskRequest(Bean Validation) |
| description | 500文字以内 | 同上 |
| フロント側 | タイトル空の間は追加ボタン非活性、maxLengthで文字数制限 | TaskForm.tsx |

## 3. 例外・トランザクション方針

- 対象が存在しない場合は Service で `NotFoundException` を送出し、`GlobalExceptionHandler` が404 + `{"message"}` に変換する
- バリデーション違反は同ハンドラが400 + `{"message"}` に変換する
- トランザクション境界は Service(クラスに `@Transactional(readOnly = true)`、更新系メソッドに `@Transactional`)

## 4. シーケンス図

タスク管理には複雑な処理(複数テーブル更新・条件分岐の多い計算等)が存在しないため、対象なし。
複数テーブルにまたがる更新や在庫計算のような処理を持つ機能では、その処理に限りシーケンス図を作成すること。
