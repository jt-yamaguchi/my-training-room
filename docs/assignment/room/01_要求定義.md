# 要求定義書 — 会議室予約システム

| 項目 | 内容 |
|---|---|
| 文書の位置づけ | 発注者(業務側)からの要求。受講者はこれを起点に基本設計から作成する |
| 発注者 | 総務担当(想定) |

## 1. 背景

会議室の利用が、ドア前のホワイトボードへの手書きと口頭・チャットでの声かけで管理されており、以下の問題が起きている。

- 同じ時間帯に2組が同じ会議室を使おうとする(ダブルブッキング)が月に何度も起きる
- 空いている会議室を探すには、フロアを歩いて各部屋のホワイトボードを見るしかない
- 誰がいつまで使っているのか分からず、声をかけて確認する手間が発生している

## 2. 目的

会議室の予約を一元化し、**「どの部屋がいつ空いているか」が誰でもすぐ分かり、同じ時間帯の重複予約が起きない状態**を作る。

## 3. ステークホルダー

| 立場 | 関与 |
|---|---|
| 社員 | 会議室の空きを確認し、予約・取り消しを行う |
| 総務担当 | 会議室の登録・整理(部屋の増減や名称変更)を行う |

## 4. 実現したいこと(要求)

| # | 要求 |
|---|---|
| R-1 | 予約対象の会議室を登録・整理できること |
| R-2 | 会議室・日時を指定して予約を登録できること |
| R-3 | 会議室ごと・日付ごとの予約状況(空き状況)が一覧で分かること |
| R-4 | **同じ会議室の同じ時間帯に、重複した予約が登録できてしまわないこと** |
| R-5 | 予定がなくなった予約を取り消せること |

## 5. スコープ外(今回はやらないこと)

- ユーザー認証・権限管理(予約者は名前の入力で代替する)
- 定期予約(毎週◯曜など)・予約のリマインド通知
- 設備(モニタ・電話会議機材など)の管理・検索
- 社外向けの貸し出し管理

## 6. 制約

- お手本(タスク管理アプリ=training-task)と**同じ技術スタック・同じアーキテクチャ**で実現すること
- 開発ルール(CLAUDE.md)に従うこと
